CRITICAL ISSUES IDENTIFIED
═══════════════════════════

Issue #1: DISTRIBUTED RATE LIMITING REQUIRED
Severity: MEDIUM
Location: dashboard/lib/rate-limiting.ts (line 104)

Problem:
  Rate limiter uses in-memory Map<string, RateLimitStore>. This store is per-process.
  In a load-balanced environment with multiple Node.js processes, each process has
  its own counter. An attacker can bypass rate limits by distributing requests.

Attack Vector Example:
  Limit: 5 requests per minute per IP
  Setup: Load balancer distributes to Server A and Server B

  Server A counter: 0 → 1 → 2 → 3 → 4 → 5 [RATE LIMITED]
  Server B counter: 0 → 1 → 2 → 3 → 4 → 5 [RATE LIMITED]

  Total requests allowed: 10 (should be 5)
  Effective limit per server: Bypassed

Impact:
  - Brute force attacks on login endpoint can succeed in distributed setup
  - DDoS protection fails if attacker can distribute requests
  - Single server: ✅ Works correctly
  - Multiple servers: ❌ Rate limit ineffective

Solution: Implement Redis-based distributed counter

Effort: 2-3 hours
Complexity: LOW

Recommended Fix:
  1. Add Redis client (npm i ioredis)
  2. Replace Map with Redis INCR/EXPIRE
  3. Update key generation to include endpoint
  4. Add fallback to in-memory if Redis unavailable

Code snippet:
```typescript
import Redis from 'ioredis'

const redis = new Redis(process.env.REDIS_URL!)

export async function checkRateLimit(endpoint: string, key: string, limit: number, window: number) {
  const redisKey = `rate-limit:${endpoint}:${key}`
  const current = await redis.incr(redisKey)

  if (current === 1) {
    await redis.expire(redisKey, Math.ceil(window / 1000))
  }

  const ttl = await redis.ttl(redisKey)
  const resetTime = Date.now() + (ttl * 1000)

  return {
    allowed: current <= limit,
    count: current,
    remaining: Math.max(0, limit - current),
    resetTime
  }
}
```
